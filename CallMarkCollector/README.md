# 来电标记采集助手（Kotlin / Android 14～16）

这是一个独立 Android 项目，包名为 `com.example.callmarkcollector`，不会与“校园导览助手”混合。应用通过电话状态监听确认响铃，再使用无障碍服务读取来电界面的可见文本，提取主叫号码、是否被标记、标记人数和标记类型。每生成一条记录都会调用上传入口。

## 环境

- Android 14（API 34）及以上手机
- `compileSdk = 36`、`targetSdk = 36`、`minSdk = 34`
- Android Gradle Plugin 8.13.2
- Gradle 8.13
- Kotlin 2.2.21
- JDK 17

## 首次使用

1. 安装并打开应用。
2. 点击“授权读取响铃状态”，允许电话状态权限。
3. 点击“打开无障碍设置”，手动开启“来电标记识别服务”。
4. 在首页填写完整 POST 接口地址并保存。暂时留空也会保存历史，但不会联网。
5. 来电后在“查看来电历史记录”中查看详情、原始文字和上传状态；可删除单条或清空本地记录，也可对失败记录手动重试上传。

系统禁止普通应用静默开启无障碍服务，因此第 3 步必须由设备使用者亲自确认。

## 识别与上传流程

```text
电话状态进入响铃（需要 READ_PHONE_STATE 权限）
        ↓
立即创建本地采集记录；最多 8 秒，每 600ms 补读一次
        ↓
选择电话窗口/来电卡片，排除自己的页面，读取可见节点
        ↓
解析号码、标记人数、标记类型
        ↓
合并同号码字段；8 秒到期或响铃结束时完成同一条记录
        ↓
持久化最终记录，再按 recordId 领取一次上传任务
        ↓
接口已配置：POST JSON；否则标记未配置，保留历史并支持手动重试
```

## 日志

主要 Logcat 标签：

- `CallMarkCapture`：服务生命周期、电话状态、窗口节点、采集会话
- `CallMarkParser`：内置解析测试结果；实际窗口候选结果在 CallMarkCapture 中
- `CallMarkUpload`：记录 ID、HTTP 状态或异常
- `CallMarkUI`：权限和接口配置变化

查看日志：

```powershell
.\运行来电标记采集.ps1 -跳过清理 -查看日志
```

也可以直接执行：

```powershell
adb logcat -s CallMarkCapture:D CallMarkParser:D CallMarkUpload:D CallMarkUI:D *:S
```

## Windows 一键运行

在项目根目录打开 PowerShell：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\运行来电标记采集.ps1
```

仅测试并构建 APK：

```powershell
.\运行来电标记采集.ps1 -仅构建
```

## 兼容边界

- 不同品牌的电话应用可能使用不同文案、视图结构，甚至不向无障碍公开敏感文字。解析器已避免依赖固定控件 ID，但不能保证覆盖所有 OEM。
- 第一次真机测试时，请检查 `rootPackage/window/selected/raw` 日志；新标签可在 `CallScreenParser.kt` 的 `knownLabels` 中补充。
- 为可靠按次触发，未授予电话状态权限时不再仅凭界面文字创建来电记录。需要同时启用电话状态权限和无障碍服务。
- 连续重复铃声属于同一通来电，不会重复建记录；通话结束后同号码再次来电会建新记录。8 秒补读期内允许补全人数，期满后不再改变已上传内容。
- 读不到的字段保留 null；完全读不到号码也保存并提交一条 NO_NUMBER 结果。服务端须接受这些空值，详见接口约定。
- 删除仅影响本地记录，未发送的任务会跳过；已发出的请求无法撤回，已上传的数据不会自动从服务端删除。
- 项目不读取通讯录和通话记录，也不尝试绕过系统权限。仅应部署在已取得设备使用者授权的场景。
- 当前版本允许 HTTP 便于内网调试；生产环境应使用 HTTPS，并在服务端增加鉴权、限流、去重及隐私合规措施。

服务端字段说明见 [服务端接口约定.md](服务端接口约定.md)。
