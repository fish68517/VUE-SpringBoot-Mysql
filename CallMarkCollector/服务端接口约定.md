# 服务端接口约定（预留）

客户端允许在首页填写完整接口地址，例如：

```text
https://server.example.com/api/v1/call-screen-records
```

每次电话状态进入响铃，先创建本地记录；最多等待 8 秒补全字段，或在响铃结束时提前完成，再调用一次上传入口，以 `POST` 发送 `application/json; charset=utf-8`。重复的窗口事件不会再提交。接口为空时标记为未配置，不会联网；配置后可从历史详情手动重试。

请求头：

```text
Content-Type: application/json; charset=utf-8
Accept: application/json
X-Install-Id: <应用首次运行生成的随机 UUID>
Idempotency-Key: <recordId>
```

请求体示例：

```json
{
  "recordId": "7b741293-bb09-47ce-a774-39d551f40d01",
  "installationId": "1f5a7c22-25db-4d03-8afe-e8ee9035364b",
  "phoneNumber": "13800138000",
  "isMarked": true,
  "markCount": 23,
  "markType": "疑似诈骗",
  "sourcePackage": "com.android.dialer",
  "sourceWindowId": 42,
  "captureStatus": "CAPTURED",
  "captureReason": "采集窗口结束",
  "capturedAt": 1790143200000,
  "rawTextLines": ["来电", "138 0013 8000", "被23人标记", "疑似诈骗", "接听", "拒绝"],
  "androidVersion": "16",
  "sdkInt": 36,
  "deviceModel": "Google Pixel 9",
  "appVersion": "1.0.0"
}
```

建议服务端返回 HTTP 200～299。客户端会在状态页展示响应结果；非 2xx、超时和网络异常均会写入 `CallMarkUpload` 日志。

## 本次新增字段与空值

| 字段 | 含义 |
| --- | --- |
| recordId | 每个响铃会话的 UUID；重试时保持不变 |
| phoneNumber | 字符串或 null；不可转换为数字，以免丢失座机开头的 0 |
| isMarked | true / false / null；null 表示没有明确证据，不能当成 false |
| markCount | 非负整数或 null；null 不等于 0 |
| markType | 字符串或 null |
| captureStatus | CAPTURED：已读取可信号码；NO_NUMBER：未读取到可信号码 |
| captureReason | 采集结束或缺失原因 |
| sourceWindowId | 此次 Android 窗口 ID 或 null，仅供诊断，不作为持久业务主键 |
| sourcePackage | 实际候选窗口的根包名；无可信候选时为 unknown |
| capturedAt | 本次响铃会话开始的毫秒时间戳 |
| rawTextLines | 同一次来电、同号码的候选原始文本；没有候选时为空数组 |

字段缺失时仍提交一条结果，例如 NO_NUMBER 记录中的 phoneNumber、isMarked、markCount、markType 均可为 null。这是记录扫描失败的结果，不是捏造一个号码。若现有服务端要求这些字段非空，需要同步调整校验。本项目未包含服务端源码，本次没有部署或验证真实接口。

## 去重、失败和删除

- 客户端自动上传采用本地 PENDING → UPLOADING 的原子领取，按记录 ID 更新结果，避免事件重复请求和跨记录状态覆盖。
- 服务端应以 `installationId + recordId` 设置唯一约束，同时接受 `Idempotency-Key`。重复请求返回原结果，不能重复插入。
- 网络超时、进程中断无法证明服务端未收到；客户端不会无限自动重试。用户可在详情中手动重试，沿用同一 recordId。仅靠客户端无法保证网络层“恰好送达一次”。
- HTTP 重定向不自动跟随，应配置最终接口地址。HTTP 非 2xx、网络异常保存在对应历史记录中。
- 应用重新运行时恢复尚未领取的 PENDING 任务；上次进程中断时处于 UPLOADING 的记录标为 INTERRUPTED，等待人工重试确认。
- 删除本地记录后，队列中尚未发送的任务会跳过；已经发送的请求无法撤回，迟到的响应不会恢复本地记录。没有约定远程删除接口，因此不会删除服务端数据。
- 请求体不含本地 uploadState、uploadStatus、uploadAttempts 等控制字段。

正式部署建议使用 HTTPS，并根据业务要求增加令牌、签名、重试队列和数据脱敏。本示例没有预置任何真实服务器密钥。
