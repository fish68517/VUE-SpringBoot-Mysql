# 大屏高德地图与图表修复说明

日期：2026-09-22。

后续同日补齐：移动地图现已复用高德视图，见[移动端高德地图修复说明](移动端高德地图修复说明.md)。下文“大屏”部分描述首次接入范围；移动端默认底图及任务地图行为以新增说明为准。

## 本次修改

根据本次明确要求，大屏接入高德地图。此要求覆盖原开发方案中“大屏不接真实 GIS 底图”的限制；其他业务仍使用项目本地数据，未新增数据库、真实设备控制或云端同步。

### 大屏地图

- 大屏中央使用高德 JS API 2.0 的道路、地名和地理底图，支持拖动、缩放、深色/标准底图切换及定位复位。
- 已从用户提供的需求 TXT 中读取高德 Key 和安全密钥，写入 `code/config/amap.local.json`，无需用户再次填写。此文件已加入 Git 忽略；源码只提交空值模板 `amap.example.json`。复制项目到其他电脑时需要同时复制本地配置。
- 中原区、二七区、管城回族区、金水区、惠济区采用高德行政区查询返回的中心；郑东片区采用高德对郑东新区管委会的地址查询结果作为汇总锚点。这些标记明确表示区域汇总，不代表设施安装位置。
- 点击区域汇总可联动该区域的设施与压力曲线，卡片也可以切换具体设施、查看详情和关联告警。
- 原数据 `position` 是 1000 × 600 示意空间坐标，不是经纬度。因此大屏不将旧管线折线或设施坐标投影成虚假的真实管网。现场设施精准落点需要后续提供真实经纬度。原业务地图、框选、巡检和审核编辑功能保持原数据语义。
- 地图加载失败会显示原因提示及重试入口；地图失败不影响本地图表。页面隐藏/离开时销毁地图实例，返回时重新初始化。

### 图表错误分析与修复

旧 `ChartView.vue` 通过动态 `<script>` 加载 `./static/vendor/echarts.min.js`。该文件由 `scripts/prepare.mjs` 从依赖目录复制，同时又被 Git 忽略。图表错误提示来自这一步的加载失败，和高德 Key 无关。

旧方式有三个脆弱点：静态文件必须事先准备；相对 URL 受页面与托管目录影响；失败后的全局 `__waterChartLoad` Promise 没有清除，后续图表会继续复用失败状态。仅凭截图不能判断当时是文件缺失、路径错误还是网络加载被阻断。

本次改为在 renderjs 中按需引入 ECharts 的折线图、坐标系、提示框和 Canvas 渲染器，交给项目编译器处理依赖。所有使用 `ChartView` 的页面不再动态请求旧 vendor 文件，也不再共享失败的加载 Promise。保留已有尺寸监听、页面隐藏后的释放和返回后的重绘。

## 当前运行与配置

在 `code` 目录执行 `npm run dev:h5`，本次开发预览地址为：

`http://127.0.0.1:5173/web/`

桌面登录管理员后进入大屏。高德底图需要网络；压力曲线仍使用本地业务数据。

本项目继续保持纯前端模式，目前采用高德官方支持的浏览器安全密钥配置方式，配置在 SDK 加载前生效。浏览器地图凭据会随前端代码到达客户端，Git 忽略不等于客户端保密。若以后配置服务端安全代理，可在本地配置中填写 `serviceHost` 并清空 `securityJsCode`；本次没有创建或部署代理服务器。

发行检查仅允许明确配置的高德浏览器凭据，不放行需求文档中的 uniCloud ClientSecret、SpaceId 或其他部署参数。自动化证据只记录资源域名和路径，不记录带 Key 的请求查询串。
