### 1.2 本期架构决策

采用 **uni-app（Vue 3，普通 Vue 页面）+ 本地 JSON Mock 数据 + 前端状态管理 + uniCloud 前端网页托管**。同一工程通过 HBuilderX 发布 Web/H5 和 Android App。

业务数据源统一放在 `code/data`，演示账号、密码和角色配置统一放在 `code/account`，所有程序、构建脚本、测试和构建产物放在 `code`。开发文档和交付说明放在 `doc`。

本期不建设业务后端、数据库、云函数、生产权限中心、设备接入服务和高可用架构。无需 Spring Boot、MySQL/PostgreSQL、Windows Server 2019，也无需购买业务服务器。工作目录名称不作为技术选型依据。

uniCloud 在本项目中承担静态网页托管。前端网页托管与云函数没有绑定关系，因此无需为了托管页面而实现业务云函数。[官方依据：uniCloud 前端网页托管](https://doc.dcloud.net.cn/uniCloud/hosting.html)

### 1.3 原始清单与本期要求的解释

| 原始描述 | 本期实现 | 验收边界 |
| --- | --- | --- |
| 本地化/云化部署、Windows Server、MySQL/PostgreSQL | H5 静态资源部署至 uniCloud 前端网页托管 | 页面可访问，静态资源完整，主要交互可用 |
| GIS、SCADA、IoT 接口对接 | 本地管网示意地图、设备曲线、数据接入展示 | 不发送第三方业务请求，不接入真实设备 |

| 5 万点接入授权 | 展示“规划接入规模 50,000 点（模拟）”及实际样例点数 | 不验收 5 万点连接、授权或采集吞吐量 |
| 采样频率 1 秒至 5 分钟 | 前端回放步长配置 1—300 秒 | 改变样本选取与演示节奏，不代表设备采样配置 |
| 阀门远程通断、泵机启停 | 确认后改变本地状态，写入模拟操作历史 | 不生成真实控制指令 |
| 短信、邮件推送 | 生成渠道为短信/邮件的模拟通知记录 | 明示“模拟发送”，不显示为真实送达 |
| 审核、正式入库 | 前端审核状态机，审批完成后更新本机有效数据集 | 不写入数据库，不跨设备同步 |
| 视频统一管理 | 本地演示片段播放、通道切换和离线状态展示 | 不接真实摄像头、监控平台或直播流 |
| 移动端与一张图打通 | 共享数据源、实体 ID、业务规则及路由语义 | 各设备独立状态，支持手动迁移演示快照 |

首版使用自制供水示意图及本地坐标。2026-09-22 按用户追加要求，大屏及移动地图使用 TXT 中提供的高德配置加载真实底图、行政区查询和地址查询；不启用 GPS 定位、不新增 uniCloud 上传或第三方设备控制。原管网数据仍使用本地示意坐标。

服务空间名称 `smart-water` 仅作为待核对的部署目标，不据此推断已开通网页托管。原文中的上传域名、下载域名、request 域名不等于网页托管访问地址。业务代码不使用提供的 ClientSecret、安全密钥或云 API 域名，也不把原始需求 TXT 上传到网站。

## 3. 双主题视觉规范

### 3.1 大屏：按例图 1 的配色与结构设计

例图 1 是重庆防汛场景，本项目只借鉴视觉语言。标题、图层、指标和地名改为供水演示内容，不沿用洪水预警业务、重庆地名或截图中的具体数据。

采用顶部标题栏、中央主地图、左右透明面板、底部趋势区。地图约占主要内容面积的 55%—65%，面板不遮挡被选设施。区域边缘细线、管网流向光点和选中高亮控制在局部，避免全屏闪烁。可关闭动画。

| 设计变量 | 建议值 | 用途 |

| `--screen-bg` | `#081F33` | 大屏背景 |

| `--screen-header` | `#133F70` | 顶部标题区 |
| `--screen-panel` | `rgba(8,35,61,0.88)` | 信息面板 |

### 4.4 数据加载与保存规则

1. 初始 JSON 通过生成的导入索引进入应用包，页面经仓储访问。示例媒体以本地静态资源路径加载。
2. 应用启动按 `datasetVersion` 加载基础数据；有匹配版本的本机快照时恢复该快照。
3. 表单提交由领域服务校验、生成新状态、一次性保存，再更新 store 与图表。保存失败显示失败原因，不提前显示“已保存”。
4. 基础 JSON 是只读模板。网页操作不能直接写回源代码目录，修改结果保存于当前浏览器或 App 的本地存储。
5. 修改 `code/data/*.json` 或 `code/account/*.json` 后执行校验、准备资源并重新发行。H5 重新上传后可使用新数据；Android 内置数据变更需要重新打包安装。
6. 调整数据结构或基线时递增数据版本，旧快照不自动覆盖新基线。提示先导出旧演示状态，再重置或导入兼容快照。
7. 重置场景恢复该场景初始 JSON，清除本地业务变更、通知和操作历史，重新计算看板。账号偏好可独立重置。

纯静态托管无法把浏览器编辑直接保存回服务器 JSON，也无法使多台设备自动同步。本期提供“导出演示快照/导入演示快照”作为手动迁移方式；快照不包含账号密码或部署参数。H5 支持 JSON 文件导入导出，Android 至少支持 JSON 文本复制与粘贴导入，不强制依赖文件管理插件。

### 5.5 状态机与跨模块联动

**告警与工单闭环：**

`待处理 → 已受理 → 处理中 → 待复核 → 已关闭`。

对应工单流程为 `待派发 → 待接单 → 处理中 → 待验收 → 已完成`，验收驳回退回“处理中”。创建关联工单后告警变为已受理，开始处理后变为处理中，提交处理结果后变为待复核，验收通过才关闭告警。不能仅因点击“处理”就消除大屏告警。

**巡检闭环：**

`草稿 → 待执行 → 执行中 → 已完成`。取消任务保存原因，不计入有效任务完成率。必填检查项全部完成才能提交；异常项必须关联工单或已登记处理说明。巡检完成不自动把维修工单标记为完成。

**点线变更审核：**

`草稿 → 待一级审核 → … → 待六级审核 → 已生效`。任一级可驳回到待修改，重新提交从一级开始，原历史保留。演示节点暂命名为资料检查、位置检查、属性检查、关联检查、业务复核、发布确认，由管理员逐步模拟操作。操作员与访客不能跳过审核。被管线、任务引用的设施禁止直接删除，先解除或变更关联。

**模拟设备控制：**

阀门详情显示当前模拟状态；点击开启/关闭后填写原因、确认模拟操作，再更新状态与操作日志。关联地图立即刷新。取消确认不改状态，重复提交不重复记账；工单关闭不自动触发阀门控制。

**回放与去重：**

回放事件以 `scenarioId + eventId` 标识，同一场景事件只应用一次。暂停后不推进业务时间；切场景先停止定时器再加载数据。主动重置才清除事件应用标记。页面隐藏和 App 进入后台时暂停回放，恢复时继续原进度。

### 5.6 统计口径

| 指标 | 本期演示公式/规则 |
| --- | --- |
| 有效未关闭告警数 | 当前权限/区域内状态不为已关闭的告警计数 |
| DMA 净供水量 | 同一期间入口表累计增量合计 − 出口转供表累计增量合计 |
| 演示漏损量 | 净供水量 − 分表合计用水量 − 已登记合理未计量用水量 |
| 漏损率 | 演示漏损量 / 净供水量 × 100%；分母为0时显示不可计算 |
| 总分表比率 | 分表合计用水量 / 同期总表进水量 × 100% |
| 产销差量/率 | 同期生产供水量 − 售水量；差量/生产供水量 ×100% |
| 任务完成率 | 已完成有效任务数 / 有效任务总数 ×100%，无任务时显示“—” |
| 工作量/时长 | 有效检查项数量；执行起止区间扣除暂停后的时长 |
| 设备运行时长 | 所选期间内“运行”区间与查询区间交集的分钟数 |
| 电耗 | 优先取电表期末读数−期初读数；无电表时按功率曲线积分计算 |
| 单位供水电耗 | 电耗 kWh / 同期供水量 m³ |

漏损、产销差是两种口径，不使用同一个字段代替。负漏损、表计回退、分母为零、日期跨界和数据缺失均显示说明，不裁剪为看似正常的 0。报表、DMA、大屏必须共用计算函数，不能分别硬编码。

功率积分采用相邻有效样本的梯形法：`电量 = Σ[(P前 + P后) / 2 × 时间差小时数]`；超过配置允许间隔的缺口不插值补造，结果标明数据不完整。日/月报按北京时间自然日、自然月划分，查询区间统一为左闭右开。压力和DMA阈值放入场景规则文件，仅作为演示阈值，不宣称符合某项实际供水标准。

## 6. 可连续讲解的演示场景

### 6.1 场景 A：压力异常到维修闭环

1. 管理员登录，进入深色大屏，选择“压力异常”场景。
2. 地图设施点和告警卡同步高亮，点击进入浅色告警列表并预选该条告警。
3. 右侧查看压力曲线、设施位置和历史，点击紧急处理，填写原因并创建维修工单。
4. 切换操作员登录，查看分配到本人名下的工单，接单并提交模拟处理结果。
5. 管理员验收，告警关闭，处理历史包含完整过程。
6. 返回大屏，未关闭告警数减少，相关列表与地图颜色保持一致。重置后可再次演示。

### 6.2 场景 B：DMA 异常到检漏巡查

DMA 分区告警 → 查看同期计量差异与趋势 → 地图定位影响范围 → 创建检漏工单和巡检任务 → 回放轨迹及异常检查项 → 提交检漏结果 → 完成验收。默认预置合理数据和处理模板，现场可修改备注和执行人。

### 6.3 场景 C：设施纠错与审核发布

地图选点 → 修改位置/属性并提交 → 查看六级审核进度 → 管理员逐级处理 → 有效地图与设施台账刷新 → 操作日志追溯。驳回、重新提交和删除引用冲突也应有可演示样例。

### 6.4 场景 D：Android 移动巡检

手机登录 → 我的任务 → 任务设施地图 → 模拟轨迹回放 → 填写检查项、上报异常 → 查看已生成工单 → 模拟阀门操作 → 本地刷新验证状态。演示跨设备接续时，由管理员显式导出/导入快照；不得用双端各自播放相似动画冒充实时同步。

## 9. Web 部署与 Android 打包

### 9.1 uniCloud H5 发布步骤

1. 在 uniCloud 控制台核对 `smart-water` 对应的服务空间、云厂商、账号权限及网页托管开通状态，仅选择网页托管功能。
2. 在 `code` 完成依赖恢复、数据校验、静态资源准备和必要测试。
3. H5 路由使用 hash；`manifest.json` 中按实际版本设置 `h5.router.mode = "hash"`。根目录部署时基础路径为 `/`；改为子目录时同步调整基础路径与资源引用。
4. 在 HBuilderX 发行 Web/H5，确认实际输出目录，通常位于 `code/unpackage/dist/build/h5`。只上传编译后的目录内容，让 `index.html` 位于托管根目录。
5. 通过控制台网页上传产物，设置首页，核实 HTTPS、域名和静态资源路径。官方支持控制台上传静态网页。[官方依据：网页托管使用方式](https://doc.dcloud.net.cn/uniCloud/hosting.html)
6. 逐页检查直接打开带 hash 的详情地址、刷新、返回、中文资源、图表、视频及数据版本，保存真实访问记录。
7. 记录实际可访问 URL；不以云存储下载地址或云函数 request 地址代替网站地址。

默认域名用于体验测试，存在云厂商相关访问限制。官方当前列示阿里云默认域名的请求频率和每日公网 IP 数量限制。对外汇报前按实际空间复核，面向多方访问时使用已具备条件的自定义域名，并检查证书和访问环境。不要将默认测试域名视为无条件长期公开服务。[官方依据：托管域名限制](https://doc.dcloud.net.cn/uniCloud/hosting.html)

托管容量、域名要求、费用和账号权限以发布当日控制台为准，本方案不承诺免费、无限流量或已经具备开通条件。App 发行物不必上传到网页托管；如需要在线分发 APK，应另核对该服务的文件大小与下载限制。

### 9.2 Android 打包步骤

1. HBuilderX 打开 `code`，核对 uni-app AppID、应用名称、图标、启动图、版本号、Android 包名。
2. 使用普通 Vue 页面编译为 App-Android，业务数据、地图、图表库和演示媒体内置于应用。
3. 不启用定位、第三方地图、消息推送、真实视频监控 SDK。功能只使用本地示例和手动上报，不要求相机、定位或短信权限。
4. 使用 DCloud 账号登录 HBuilderX，通过 Android 云打包流程生成 APK，优先采用官方推荐的安心打包模式；核实当前版本支持与账号额度。[官方依据：App 云打包](https://uniapp.dcloud.net.cn/dev/app/cloud-build.html)
5. 准备应用签名证书、别名和密码，交付记录中说明证书归属；签名材料不放入 `code/account` 或网页产物。
6. 安装到实际 Android 设备，验证冷启动、登录、地图缩放/框选、任务上报、控制确认、本地保存、系统返回键、横竖屏和应用重启。
7. 验证断网后已安装 App 的核心演示能运行；H5 不额外承诺离线缓存或 PWA 能力。
8. 记录 HBuilderX、Android 系统、设备型号、版本号、包名和 APK 校验值。生成成功与真机验收分别记录。

### 9.3 导出与平台差异

PC/H5 列表导出采用 UTF-8 BOM CSV，正确处理逗号、双引号和换行，导出范围默认采用当前筛选条件的全部结果。CSV 中姓名、账号等可能以公式字符开头的文本按文本处理，避免表格软件误解释。

Android 中提供导出内容预览和复制；如实现文件保存，通过 `platform/export.ts` 使用 App 文件能力落盘并在真机验证。手机端最终至少提供可取出的 CSV 文本，按钮标签应与实际行为一致。快照迁移采用同一 JSON Schema，导入前校验大小、版本、角色权限及实体关联，失败时保持原状态。

| T07 | 地图选择 | 点、线、矩形、多边形及边界样例；缩放后选择对象正确 | 二 |

| T09 | 巡检 | 发布、改派、模板检查、异常工单、轨迹回放与进度统计 | 二 |
| T10 | 指标计算 | 人工小样本复算DMA/产销差/电耗/运行时长；覆盖零分母和跨日 | 二 |
| T11 | 通知视频 | 模拟通知可追踪，本地视频可播放，离线通道有明确状态 | 二 |

| T17 | 连续演示 | 连续运行30分钟，无白屏、计时器累积、重复事件和持续增长的图表实例 | 二 |

T16 是样例数据规模下的体验目标，不是生产 SLA。动画按需启用；页面隐藏停止定时器；关闭图表/地图时由宿主页向 renderjs 发出释放指令，确保事件、动画与图表实例清理，不能依赖不受支持的 renderjs 卸载钩子。

纯计算和状态迁移采用单元测试；关键闭环采用浏览器操作验证和 Android 真机验证。编译成功不等于页面、托管或设备验证成功。验收记录分别列出静态检查、自动测试、本地浏览器、线上 H5、Android 五类证据。
