# 移动端高德地图修复说明

日期：2026-09-22。

## 2.0.2 修复：Android 一直显示“正在加载高德地图”

本项目在 App WebView 中调用高德 **JS API**，使用的是 Web 端（JSAPI）Key，不是高德 Android 原生 SDK。安装在 Android 手机上不意味着应当更换为 Android SDK Key；只有改接原生 SDK 时才使用对应平台的 Key。依据：[高德 JS API 接入说明](https://developer.amap.com/api/javascript-api-v2/getting-started)、[uni-app renderjs 的 WebView 运行说明](https://uniapp.dcloud.net.cn/tutorial/renderjs.html)。

本次在项目实际使用的 `uni-app-view.umd.js` 中确认：App 将 renderjs 创建为一个独立 Vue 实例，挂载在独立的 div 中，render 函数为空；它的 `this.$el` 是未连接到页面的占位节点。可见组件的 DOM 由 `$ownerInstance` 以及 `change:prop` 回调的组件描述对象提供。H5 则将 renderjs 作为 mixin，二者不是同一种 `$el`。

2.0.1 的地图在 SDK 加载后检查 `this.$el.isConnected`，会因占位节点未连接而直接退出，而且此时地图完成超时计时器尚未启动，所以界面永久停在初始加载文案。仅修改 Key 无法修复这个代码问题。同样的取节点方式也影响了 App 管网画布与图表。

现已新增 `platform/render-host.js`，优先获取属性回调描述对象和所属组件的真实元素，三种视图都使用真实容器绘制、测量尺寸和检查卸载。地图容器缺失或离开页面会显示明确错误及重试入口。Key 未更换。

原本的 `file://` 测试把 renderjs 的 `$el` 直接设为可见 DOM，未覆盖这个 App 差异，不能证明当时 APK 中地图可用。本次将它改为未连接的注释节点，真实 DOM 放在组件描述对象中，再运行实际 renderjs 和高德 SDK；此回归及其余移动地图 5 组、移动业务 9 组、大屏图表 5 组检查均已通过。

修复版安装包：`code/unpackage/release/apk/郑州智慧供水-2.0.2-地图加载修复.apk`，版本 `2.0.2` / `202`，沿用原包名和证书。未自动安装或操作已连接手机的界面，真机地图效果需安装本版后确认；本次读取到手机仍安装的是 `2.0.1` / `201`。

> 同日交付更新：用户随后要求直接打包，已生成 `code/unpackage/release/apk/郑州智慧供水-2.0.1-移动地图.apk`，版本 `2.0.1` / `201`。APK 签名、版本、联网权限和最新地图资源已校验，未进行 Android 真机安装验证。详见[Android 打包交付记录](HBuilderX打包Android安装说明.md)。下文“不制作 APK”记录的是前一次源码修复的验证范围。

## 问题原因

此前高德地图只接入大屏，移动页 `MapPanel.vue` 仍调用 `MapCanvas.vue`，绘制的是本地管网示意坐标，没有加载高德底图。这与 Key 是否已经提供无关。

另外，旧画布在 renderjs 挂载时读取 `this.prop`，没有可靠处理“属性先到达、视图后挂载”的初始化顺序。这种顺序在 App 逻辑层与视图层之间可能出现；本次改为先缓存配置，容器挂载后初始化。仅凭截图不能确认当时手机空白的全部运行时原因，未将浏览器验证描述为该手机的现场复现。

回归中还发现：高德 JS API 2.0 动态切换样式后立即销毁地图，尚未完成的样式请求可能访问已释放对象，报 `Cannot read properties of undefined (reading 'pn')`。现改为创建实例时设置目标样式，切换时重建并清理旧实例；快速切换图层回归未再捕获该异常。

## 已完成修改

- **移动地图默认显示高德郑州道路和地名底图**，支持触摸拖动、缩放、放大/缩小按钮、复位及深浅底图切换。
- 复用现有 `code/config/amap.local.json` 中已提供的高德浏览器 Key 和安全配置，无需再次填写。通过 renderjs 在 H5 / App 的视图层调用 JS API；本次没有改成 Android 原生地图 SDK。
- 点击区域标记可筛选该区域设施并展开结果台账；点击设施可查看详情、告警及有权限的业务操作。
- 从巡检任务进入地图时，只统计该任务关联设施；单区域任务会自动聚焦该区域。角色权限和原有任务范围保持一致。
- “图层 → 管网视图”保留原管线、设施点选及矩形框选；选择“浅色底图”或“深色底图”可返回高德地图。框选只作用于原管网视图，避免把示意坐标当成地理坐标使用。
- 地图失败显示重试入口；返回页面时重新初始化。补充视图挂载时序、尺寸监听兼容处理，并限制地图内部层级，避免覆盖手机导航或详情抽屉。

**数据含义：** 当前设施 `position` 是 1000 × 600 示意坐标，尚无真实经纬度。高德地图上的标记是区域汇总锚点，不是具体水表、阀门或管道的安装位置。五个行政区使用高德行政区查询结果，郑东片区使用管委会地址查询结果。精确设施落点和真实管线走向仍需补充现场经纬度数据；本次未伪造这些数据，也未新增 GPS 定位或真实设备控制。

## 查看方法

1. 在 `code` 目录运行 `npm run dev:h5`，访问终端显示的开发地址。本次使用 `http://127.0.0.1:5173/web/`。
2. 使用手机尺寸进入登录页并登录，点击底部“地图”，应看到道路、地名及区域标记。也可从“任务 → 任务地图”进入查看任务范围。
3. 点击“图层”切换深浅底图或管网视图；点击“结果”查看设施列表。
4. **手机中已安装的旧 APK 不会随源码自动更新。请自行在 HBuilderX 重新打包并安装本次源码生成的安装包。** 本次没有制作 APK、更新发行资源或上传 uniCloud。

已有本地配置需要随项目保留；该文件被 Git 忽略，单独从 Git 获取源码时应按 `amap.example.json` 模板恢复配置。地图需要联网。如果出现加载失败，可先恢复网络再点击“重新加载地图”。
