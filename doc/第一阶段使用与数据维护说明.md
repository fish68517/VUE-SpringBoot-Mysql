# 第一阶段使用与数据维护说明

## 1. 启动与入口

在项目 `code` 目录执行 `npm ci`、`npm run prepare:demo`、`npm run dev:h5`，打开终端显示的 `http://127.0.0.1:5173`。本地发行版本使用 `npm run build:h5` 后运行 `npm run preview`，访问 `http://127.0.0.1:4173`。

依赖锁文件已生成，日常使用 `npm ci` 恢复版本。本工程曾遇到 npm 官方源的 TypeScript 元数据获取异常，安装时改用 npm 镜像完成；未使用 `--force` 或 `--legacy-peer-deps` 绕过依赖冲突。无需修改全局 npm 设置。

HBuilderX 打开 `code` 工程，源码在根目录。CLI 脚本增加了可复现的本地构建方式，没有改变 uni-app 普通 Vue 页面和 HBuilderX Android 打包路线。

## 2. 演示角色

管理员、中原区操作员和访客均可通过登录页点击角色自动填入凭据。完整账号密码集中放在 `code/account/users.json`，阅读说明见 `code/account/README.md`，仅为虚构演示身份。

管理员处理全局调度、派单、验收和场景重置。操作员只能访问授权区域，并处理本人任务/工单。访客可只读查看，不能通过详情页绕过动作校验。前端角色控制只用于业务演示。

## 3. 建议演示顺序

### 场景 A：告警闭环

1. 管理员登录，在“演示设置”选择“压力异常处置”，确认重置。
2. 进入大屏，点击第一条“管网压力偏低”，进入告警 `ALM-001`。
3. 点击“受理并分配”，选择“陈明（演示）”，输入处置要求，创建维修工单。初始数据未增加其他工单时编号为 `WO-041`，以页面实际编号为准。告警详情同步生成短信/邮件模拟通知记录，不执行真实发送。
4. 退出，使用 `operator` 登录。在工单中心找到刚才的工单，接单并开始处理。
5. 填写处理结果，点击“提交验收”。操作员不能自行验收。
6. 退出，管理员登录并查看同一工单，点击“验收通过”并确认。需要演示驳回时，填写原因后驳回重处理。
7. 返回告警详情，状态为“已关闭”；返回大屏，待闭环告警从初始 23 条减少为 22 条。刷新后仍保留状态。
8. 再次进入演示设置重置，恢复初始 23 条未关闭告警和 40 条工单。

### 场景 B：基础巡检

管理员可以发布任务，选择区域、日期、执行人和设施。进入任务详情，分别填写检查结果和说明。异常检查项保存后会生成巡检类型工单，可以从任务详情进入处理。所有检查项完成才能提交巡检；巡检完成不会自动完成异常维修工单。

阶段一提供固定的基础检查模板和本地样例附件。轨迹回放、模板设置、路线配置和任务改派扩展在第二阶段实施。

### 地图、DMA与报表

地图支持点选设施/管线、拖动平移、滚轮或按钮缩放、底图切换、管线显隐、查询和设施分页。底图为自制本地示意坐标，不是真实 GIS。

DMA 详情显示净供水、演示漏损、总分表比率和产销差，可进入对应地图、告警和检漏工单创建页。用水报表有 2026 年 9 月 30 天数据，压力报表有 9 月 20 日逐小时样例；不存在的时段显示无数据，不补成零。

PC 告警与报表导出实际 CSV 文件；App 平台的基础导出适配采用 CSV 文本复制。完整移动交付和文件能力真机验证在第二阶段。

## 4. 修改 JSON

| 需要修改的内容 | 源文件 |
| --- | --- |
| 设施名称、类型、位置、区域 | `code/data/facilities.json` |
| 管线端点、路径、管径 | `code/data/pipes.json` |
| DMA 水量和阈值 | `code/data/dma.json` |
| 告警级别、状态、历史 | `code/data/alarms.json` |
| 工单和巡检台账 | `code/data/workorders.json`、`inspections.json` |
| 设备与压力曲线 | `code/data/devices.json`、`metrics/series.json` |
| 居民日用水量 | `code/data/metrics/usage.json` |
| 公告、动态、通讯录 | `code/data/portal.json` |
| 模拟场景初始时间 | `code/data/scenarios/*.json` |
| 账号、区域权限 | `code/account/users.json`、`roles.json`、`permissions.json` |
| 本地示例附件 | `code/data/assets/` |

保持 ID 唯一，修改名称不修改其他表中引用的 ID。新增告警时设施必须存在，新增任务时执行人必须拥有该区域权限。坐标以 `1000 × 600` 本地画布为参考，压力 MPa、水量 m³。数字保持 JSON 数值，缺失值使用 `null`。

执行：

```powershell
cd code
npm run data:check
npm run prepare:demo
npm run check
npm test
npm run build:h5
```

`prepare:demo` 会把 `data/assets` 媒体复制到 `static/demo-assets`；只修改源目录，不修改生成副本。更改数据基线时递增 `data/manifest.json` 的 `datasetVersion`，避免旧本机状态覆盖新种子。

## 5. 本机保存与重置

网页和 App 的表单操作保存在当前设备本地，不会写回源 JSON，不会同步其他浏览器和手机。三种角色在同一浏览器内切换时共享本机业务记录，符合现场演示闭环。

遇到旧版本或损坏的本机状态，系统显示原因并阻止新业务写入，管理员通过“演示设置”确认重置后恢复。存储写入失败时操作不会先显示成功。

阶段一没有快照迁移功能，不要把 PC 和手机同时播放相似数据描述为实时同步。
