# 电网设备巡检管理系统功能清单与开发计划

## 1. 设计依据

根据《2230090216祁思妤-开题报告-基于Spring Boot的电网设备巡检管理系统设计与实现》的研究内容，系统建设目标应围绕以下重点展开：

- 面向电网设备巡检业务，解决传统纸质巡检、人工汇报、异常响应慢、追溯困难等问题。
- 建立覆盖设备档案、巡检任务、巡检记录、异常上报、维修处理、统计分析的闭环管理体系。
- 支持多角色协同，提升巡检效率、数据准确性和异常处置效率。
- 系统采用 `Spring Boot + Vue + MySQL` 构建 Web 网页系统，满足毕业设计实现难度与可落地性要求。

## 2. 系统建设目标

本系统定位为一个基于 B/S 架构的电网设备巡检管理平台，服务于设备巡检全过程管理。系统需要完成以下建设目标：

- 建立统一的设备基础档案，支持设备信息规范化管理。
- 建立巡检计划、巡检任务与巡检记录之间的业务关联，实现任务下发与执行留痕。
- 建立异常缺陷上报和维修工单闭环机制，实现从发现问题到维修完成的全过程跟踪。
- 建立统计分析与报表能力，为管理员掌握设备状态、巡检质量和维修效率提供依据。
- 建立清晰的 RBAC 权限模型，仅保留 `管理员`、`巡检员`、`维护员` 三类用户。

## 3. 技术约束与基础环境

- 后端框架：`Spring Boot`
- 前端框架：`Vue`
- 数据库：`MySQL`
- 系统形态：`Web 网页系统`
- 数据库账号：用户名 `root`
- 数据库密码：`root`
- 建议数据库名：`power_inspection`
- 建议前后端架构：前后端分离，后端提供 RESTful API，前端负责页面展示与交互

建议数据库连接参数如下：

```properties
spring.datasource.url=jdbc:mysql://localhost:3306/power_inspection?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai
spring.datasource.username=root
spring.datasource.password=root
```

## 4. 用户角色设计

### 4.1 管理员

管理员负责系统基础数据维护与业务统筹，主要职责包括：

- 用户信息维护、角色分配、账号启停
- 设备档案维护、设备分类维护、巡检标准维护
- 巡检计划制定、巡检任务派发、巡检结果审核
- 异常工单分派、维修闭环确认
- 统计报表查看、系统公告发布、日志审计

### 4.2 巡检员

巡检员负责执行巡检任务与现场信息反馈，主要职责包括：

- 查看个人待办巡检任务
- 按设备和巡检项目填写巡检结果
- 上传巡检时间、巡检结论、现场描述、图片附件
- 发现异常后提交异常缺陷信息
- 查看个人历史巡检记录和异常上报记录

### 4.3 维护员

维护员负责接收维修工单并完成处理闭环，主要职责包括：

- 查看分配给自己的维修工单
- 填写维修过程、处理措施、处理结果
- 上传维修完成时间、维修说明、维修图片
- 反馈是否修复完成、是否需要二次处理
- 查看个人维修记录与工单状态

## 5. 系统功能清单

## 5.1 公共基础功能

### 5.1.1 登录与安全认证

- 账号密码登录
- 基于角色的菜单显示与接口访问控制
- 修改个人密码
- 退出登录
- 登录日志记录

### 5.1.2 首页工作台

- 展示当前用户待办事项
- 展示任务数量、异常数量、维修数量等统计卡片
- 展示最近巡检记录、最新异常工单和通知公告

### 5.1.3 个人中心

- 查看个人资料
- 修改手机号、邮箱、头像等基础信息
- 修改密码

## 5.2 管理员功能模块

### 5.2.1 用户与权限管理

- 用户新增、编辑、删除、查询
- 三类角色配置：管理员、巡检员、维护员
- 用户状态管理：启用、禁用、重置密码
- 菜单权限与接口权限控制

### 5.2.2 设备档案管理

- 设备分类管理
- 设备台账管理
- 设备基础信息维护：设备编号、设备名称、设备类型、安装位置、投运日期、运行状态
- 设备图片、说明文档维护
- 设备状态查询与条件筛选

### 5.2.3 巡检标准管理

- 按设备类型维护巡检项目
- 维护巡检标准值、检查方法、异常判定规则
- 维护巡检周期建议，为任务制定提供依据

### 5.2.4 巡检计划与任务管理

- 制定月度或周度巡检计划
- 根据设备、区域、人员生成巡检任务
- 指定巡检员、计划时间、优先级、备注
- 任务下发、任务撤回、任务完成状态跟踪
- 查看未完成任务、逾期任务、已完成任务

### 5.2.5 巡检记录审核

- 查看巡检员提交的巡检记录
- 审核记录完整性与异常项
- 对不合格记录进行退回重填
- 对正常记录进行确认归档

### 5.2.6 异常与维修闭环管理

- 查看巡检员上报的异常缺陷
- 生成维修工单并指派维护员
- 跟踪工单处理进度：待处理、处理中、待复核、已完成
- 对维修结果进行确认，实现闭环

### 5.2.7 报表统计与系统管理

- 巡检完成率统计
- 设备异常次数统计
- 维修工单处理时长统计
- 巡检员工作量统计
- 系统公告管理
- 操作日志管理

## 5.3 巡检员功能模块

### 5.3.1 我的巡检任务

- 查看待巡检任务列表
- 按时间、状态、设备名称搜索任务
- 查看任务详情，包括设备信息、巡检项目、标准要求

### 5.3.2 巡检执行与结果填报

- 逐项填写巡检结果
- 录入正常、异常、需复检等巡检结论
- 填写现场说明
- 上传图片附件
- 提交巡检记录

### 5.3.3 异常缺陷上报

- 对巡检中发现的问题进行一键上报
- 填写异常等级、异常描述、发现时间、相关设备
- 上传现场照片
- 查看异常上报处理进度

### 5.3.4 个人记录查询

- 查看个人已完成巡检记录
- 查看个人异常上报历史
- 按时间范围导出或查询巡检数据

## 5.4 维护员功能模块

### 5.4.1 我的维修工单

- 查看待处理工单
- 查看工单设备信息、异常描述、优先级、要求完成时间
- 按状态筛选：待处理、处理中、已完成

### 5.4.2 维修处理反馈

- 填写处理过程与维修措施
- 记录更换部件、维修说明、处理结果
- 上传维修现场照片
- 提交维修完成申请

### 5.4.3 工单进度管理

- 更新工单处理状态
- 标记无法处理或需要再次派工
- 查看历史维修工单与个人维修记录

## 5.5 数据统计与业务分析功能

结合开题报告中“数据管理与应用模式”的研究方向，系统应补充以下分析能力：

- 设备维度统计：按设备类型、区域、状态统计设备数量
- 巡检维度统计：按时间、人员、设备统计巡检次数和完成率
- 异常维度统计：按异常等级、设备类型、时间统计异常分布
- 维修维度统计：统计维修闭环率、平均维修时长、超时工单数量
- 趋势分析：展示某一时间段内巡检量、异常量、维修量变化趋势

## 5.6 非功能需求

- 易用性：页面结构清晰，适合管理员、巡检员、维护员快速上手
- 安全性：基于 RBAC 的权限控制，重要操作保留日志
- 稳定性：支持日常多用户并发访问，避免任务和记录丢失
- 可维护性：前后端分离，模块清晰，便于后期扩展
- 可扩展性：后续可扩展短信提醒、消息推送、移动端巡检、小程序巡检等功能

## 6. 核心业务流程设计

### 6.1 巡检业务流程

1. 管理员维护设备档案与巡检标准。
2. 管理员制定巡检计划并生成巡检任务。
3. 巡检员登录系统查看个人待办任务。
4. 巡检员按照任务填写巡检记录并提交结果。
5. 管理员审核巡检结果，合格后归档。

### 6.2 异常闭环流程

1. 巡检员在巡检过程中发现异常并提交缺陷上报。
2. 管理员查看异常信息并生成维修工单。
3. 管理员指派维护员处理工单。
4. 维护员处理完成后提交维修反馈。
5. 管理员复核处理结果并完成闭环确认。

## 8. 推荐开发优先级

为保证毕业设计在有限时间内顺利完成，建议按以下优先级实施：

- 第一优先级：登录认证、用户管理、设备档案管理
- 第二优先级：巡检计划、巡检任务、巡检记录
- 第三优先级：异常上报、维修工单、闭环确认
- 第四优先级：统计分析、日志管理、公告管理

## 9. 结论

结合开题报告的研究目标，本系统应以“设备档案管理 + 巡检任务执行 + 异常维修闭环 + 数据统计分析”为主线，围绕 `管理员`、`巡检员`、`维护员` 三类用户设计功能边界。采用 `Spring Boot + Vue + MySQL` 构建 Web 网页系统，既符合课题技术路线，也能够较好体现电网设备巡检管理业务的完整性、实用性和可实现性。
