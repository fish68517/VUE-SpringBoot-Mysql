## 1. 到账记录

管理员在“到款记录”中可使用以下功能：

- 每条到账记录增加“删除”按钮。确认后删除流水，同时从关联项目的到款金额中扣回这笔流水的分配金额；保留其他流水和未由本笔流水产生的余额。取消确认不改数据。
- “未自动匹配”面板支持“添加关联项目”，每一行分别选择项目、手动填写关联金额，也可以移除多余行。
- 面板显示已填写合计及剩余/超出金额。金额必须大于零，最多两位小数，不允许重复选择同一项目，分配合计必须等于整笔到账金额。
- 一笔到款可分配给多个项目，确认后逐个更新到款金额，列表显示关联项目与分配金额。重复确认相同分配不会重复加款。
- 旧版单项目流水继续支持查看和删除。删除一个关联项目后，保留该流水对其他项目的分配，并可对剩余金额重新关联。

例如：到账 1000 元，分别给甲项目 600 元、乙项目 400 元。确认后分别增加 600 / 400 元，而不是两个项目各增加 1000 元。删除该流水后，分别扣回 600 / 400 元。

删除以流水中记录的分配为依据。如果历史上曾手动将项目到款总额改成与流水不一致，程序会按分配扣减并将金额下限设为零，不会自动推断或修复历史账务差异。

## 2. 预警台账

- 新增独立“维保单位”筛选，可与关键词、使用单位、预警状态组合使用。
- 管理员可以勾选设备，也可以通过表头复选框全选当前筛选结果；顶部显示选中数量，并提供“删除选中设备”。
- 切换筛选条件会清空勾选，防止删除视野外的记录。批量删除有确认提示，只删除选中的物业设备，不删除项目台账和到账流水。
- 点击左侧到期年月或右侧“编辑”，可以修改“下次检验日期”，同时保留跟进状态和备注编辑。
- 后续补充：管理员点击列表“查看”即打开可编辑的设备详情弹窗，可修改使用单位、设备品种、设备代码、单位内编号、下次检验日期、登记证编号、检测机构、单位地址、维保单位、应急电话、联系人、两个联系电话、数据来源、跟进状态和备注。设备 ID 保持不变，取消不保存。
- 编号和电话按文本保存，保留前导零；使用单位不能为空。“数据来源”修改的是记录内的来源说明，不会重命名原始 Excel 文件。
- 日期修改后，到期年月、预警状态和汇总重新计算，并按原有保存流程同步。日期留空时显示“日期待补”。
- 到期年月列保持横向滚动时固定在左侧，表头保持纵向滚动时固定在顶部。

沿用现有权限：管理员可操作，业务员对到账记录及预警台账保持只读。业务员仍可使用筛选查询；未开放新的删除或改期权限。

## 3. 数据兼容与云函数调整

新流水使用以下字段记录关联：

```json
{
  "amount": 1000,
  "projectId": "",
  "allocations": [
    { "projectId": "项目甲ID", "amount": 600 },
    { "projectId": "项目乙ID", "amount": 400 }
  ],
  "status": "已确款"
}
```

`allocations` 为新关联数据；旧记录只有 `projectId` 时，按整笔金额关联到该项目理解。新记录只有一个完整关联时，仍保留兼容用的 `projectId`；多项目或部分关联时，不用该旧字段表达完整关系。

`zsh-ledger-state` 原本保存嵌套数组，因此本次没有修改 schema，也不要求清库或批量迁移旧数据。仍通过既有 `save`、`loadMeta` 和 `loadChunk` 接口同步。

云函数的业务员读取逻辑已增加多项目关联识别：一个业务员只要拥有其中一个项目，就能读取对应付款记录；返回的关联明细仅包含其可见项目。付款金额等流水基本信息沿用原有可见方式。后端原有“业务员不能修改到账和共享设备”的保护继续保留。

后续补充“省市打款”权限：两个业务员账号在检验台账中均看不到该汇总卡、表格列和项目详情项；管理员的显示与编辑保持不变。云函数在业务员的项目响应中移除 `provincialPayment`，业务员保存其他项目字段时保留数据库里的原金额，避免字段缺省或伪造值覆盖管理员数据。此变更需要部署新云函数才能生效。

## 6. 上线时需更新的内容

1. 先将更新后的 `zsh-ledger-api` 云函数部署到网页当前使用的目标空间。
2. 更新静态网站文件，特别是 `index.html`、`app.js`、`styles.css`，以及新增的 `ledger-data.js`。新增模块遗漏会导致页面不能正常初始化。
3. 本次没有改动 `cloud-config.js` 中的实际接口地址。如果部署到新空间，需要按项目分析文档另行调整对应 URL 和域名配置。
4. 页面资源已使用新的缓存参数；请所有正在使用旧页面的账号关闭旧标签页后重新打开，避免旧客户端将多项目流水按旧规则处理。
5. 使用测试数据在实际空间复核：1000 元分为 600/400 元、刷新、删除并核对金额、筛选后批量删除、改期并刷新，以及业务员只读。
