# 防汛预警系统离线地图瓦片拼接方案

## 1. 目标与边界

在 `/waterlog-dia-bus` 的防汛预警弹窗左侧，为现有嘉陵江、长江动态水流增加真实地图底图。底图只使用项目内的离线瓦片，不请求高德服务器、不依赖后端接口，也不改变站点水位、预警计算、河道轨迹和 Canvas 粒子动画逻辑。

目标图层关系如下：

```text
离线高德瓦片底图
  └─ 深色科技风调色层与网格
      └─ Leaflet 河道 SVG（光晕、河岸、主水体、流带、水花）
          └─ Canvas 水流粒子
              └─ 站点、名称标签、预警路径、图例和 HUD
```

## 2. 现有架构定位

页面路由为 `/waterlog-dia-bus`，防汛地图实际实现在：

`src/package/BZAQ/BzWaterKpiDia/components/WaterlogPredictionDia.vue`

该组件已经使用 Leaflet 管理经纬度投影、河道折线和站点，并使用 Canvas 绘制流动粒子。因此离线地图应直接作为 Leaflet `TileLayer` 加入现有地图，不能另建一套绝对定位地图，否则拖动、缩放和 `fitBounds` 后会与河道、站点错位。

项目内 `BzWaterlogDia/components/WaterlogMapPlaceholder/index.vue` 已经提供了可复用的工程模式：通过 `require.context` 在 Webpack 编译阶段收集瓦片，再重写 `TileLayer.getTileUrl()` 返回打包后的资源地址。本方案沿用该模式，但瓦片级别、目录顺序和地图范围按本次资源重新计算。

## 3. 瓦片资源分析

### 3.1 文件结构

资源目录：

```text
src/assets/map/10/
  ├─ 418/
  │   ├─ 811.jpg
  │   ├─ ...
  │   └─ 823.jpg
  ├─ ...
  └─ 426/
      ├─ 811.jpg
      ├─ ...
      └─ 823.jpg
```

检查结果：

- 固定缩放级别：`z = 10`；
- 第一层目录：`418–426`，共 9 行；
- JPEG 文件名：`811–823`，共 13 列；
- 总数：`9 × 13 = 117` 张，目录为完整矩形，没有缺片；
- 每张瓦片均为 `256 × 256` JPEG；
- 总资源大小约 571 KB，适合直接随组件打包。

### 3.2 X/Y 方向判定

Web Mercator（XYZ）在重庆区域 `z=10` 时：

- 经度约 `106.5°` 对应 `x≈814–815`；
- 纬度约 `29.5°` 对应 `y≈423–424`。

因此当前磁盘目录不是常见的 `z/x/y.jpg`，而是：

```text
z / y / x.jpg
```

例如 `src/assets/map/10/423/815.jpg` 对应 Leaflet 坐标 `{ z: 10, x: 815, y: 423 }`。代码构建索引时必须交换目录和文件名，最终以 `${x}/${y}` 作为查找键，避免地图转置。

### 3.3 地理覆盖范围

按 XYZ 公式计算完整瓦片边界：

| 方向 | 瓦片边界 | 经纬度约值 |
| --- | --- | --- |
| 西 | `x=811` | `105.1171875°E` |
| 东 | `x=824` 的左边界 | `109.6875°E` |
| 北 | `y=418` | `31.353637°N` |
| 南 | `y=427` 的上边界 | `28.613459°N` |

现有全部站点范围为 `105.4211–106.6745°E`、`28.8742–29.9907°N`，完全落在瓦片覆盖范围内。最西南的泸州（三）和最北的鸭嘴均有底图。

## 4. 工程实现

### 4.1 Webpack 静态资源索引

使用：

```ts
const offlineTileContext = require.context(
  '../../../../assets/map/10',
  true,
  /\.jpg$/
)
```

Webpack 会把 117 张 JPEG 作为 `asset/resource` 输出为带哈希的构建资源。运行时不拼写 `src/assets` 原路径，而是读取 `require.context` 返回的真实 URL，因此开发环境和生产构建均可使用。

索引规则：

```ts
// key: ./423/815.jpg，其中 423 是 y，815 是 x
offlineTileMap['815/423'] = emittedAssetUrl
```

找不到瓦片时返回 `L.Util.emptyImageUrl`，防止浏览器产生无意义的 404 请求。

### 4.2 Leaflet TileLayer

新增离线底图图层，并在河道、站点之前加入地图：

- `tileSize: 256`；
- `minNativeZoom: 10`、`maxNativeZoom: 10`：始终读取现有 z10 瓦片；
- `minZoom: 8`、`maxZoom: 12`：允许 Leaflet 对 z10 瓦片缩放，兼容现有全站点 `fitBounds`；
- `bounds`：限制为 117 张瓦片的真实经纬度范围；
- `noWrap: true`：禁止经度方向循环复制；
- `keepBuffer: 2`：拖动时保留邻近瓦片，降低闪烁。

只保留 z10 原生图层能够避免浏览器去请求不存在的 z8、z9、z11、z12 文件，同时维持现有缩放操作。

### 4.3 深色视觉融合

原始瓦片为浅色高德底图，直接显示会破坏当前深蓝大屏风格。通过专用类 `waterlog-offline-tile` 进行无损运行时调色：

- 使用 `invert / sepia / saturate / hue-rotate / brightness / contrast` 将浅色底图转换为深蓝底图；
- 降低瓦片透明度，避免道路和地名抢夺河道视觉焦点；
- 复用现有 `water-grid` 的网格与径向暗角，压暗四周并突出两江交汇区域；
- 降低网格强度，使地图道路、行政地名、河流动画三者均可辨识。

调色只作用于底图瓦片，不会改变河道、站点标签或预警颜色。

### 4.4 生命周期与容错

- 地图重建时由 `map.remove()` 一并销毁瓦片层；
- 组件卸载时释放 Leaflet 地图、Canvas 动画、ResizeObserver 和定时器；
- 资源缺失时显示 Leaflet 空白图，而 `.map` 原有深色渐变仍作为兜底背景；
- 不新增 Axios 请求、Token、CDN 或线上地图服务。

## 6. 验收方案

### 6.1 构建验收

1. Vue SFC 模板、TypeScript、SCSS 单文件编译通过。
2. `npm run dev` 的 Webpack 编译通过。
3. 浏览器 Network 中地图瓦片来自本地 `assets/*.jpg`，不出现高德或其他地图网络请求。
4. `git diff --check` 通过。

### 6.2 页面验收

访问：

`http://127.0.0.1:8085/waterlog-dia-bus`

点击“打开选中弹窗”后检查：

1. 左侧不再是纯渐变背景，能看到连续拼接的道路、行政区和地名；
2. 117 张瓦片方向正确，文字不旋转、不镜像，瓦片之间无明显缝隙；
3. 泸州（三）、鸭嘴、朝天门等站点均落在地图覆盖范围；
4. 嘉陵江蓝色水流、长江橙色水流和粒子动画仍位于对应站点之上；
5. 拖动、缩放和弹窗尺寸变化后，底图、河道、粒子、站点保持同步；
6. 右侧水位输入、重置和本地预警计算保持原有行为。

## 7. 后续扩展

当前资源只有 z10。若后续补充多级瓦片，可将目录规范统一为 `z/x/y.jpg`，并把 `minNativeZoom/maxNativeZoom` 扩展到实际级别。若需要更清晰的城区细节，应补充 z11–z13，而不是把 z10 无限放大；现有实现的瓦片索引和 Leaflet 图层结构可以直接复用。
