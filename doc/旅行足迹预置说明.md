# 旅行足迹预置说明

## 1. 当前页面如何显示足迹

旅行足迹页面位于：

- `VUE/src/views/TravelFootprints.vue`

当前显示逻辑如下：

1. 页面启动后从 `userStore` 中读取当前登录用户。
2. 取出当前用户的 `id`。
3. 使用这个 `id` 去匹配预置足迹数据。
4. 找到匹配用户后，只渲染该用户自己的足迹点。
5. 如果当前用户 `id` 没有匹配到预置数据，则页面不会显示足迹点，并给出提示。

## 2. 预置数据放在哪里

预置足迹数据文件位于：

- `VUE/src/mock/presetFootprints.js`

这个文件中维护了 20 个预置用户，每个用户都配置了中国大陆地区的足迹点，足迹数量做了 3 到 6 个不等的混合分布。

约束规则如下：

- 每个用户最少 3 个足迹点
- 每个用户最多 6 个足迹点
- 不同用户的足迹数量做了混合分布，不是统一固定 3 个点
- 所有预置地点均为中国大陆地区

每个用户结构如下：

```js
{
  userId: 1,
  username: '旅行者1号',
  footprints: [
    {
      id: 101,
      travel_record_id: 1001,
      location_name: '北京故宫',
      latitude: 39.916345,
      longitude: 116.397155,
      visit_date: '2026-01-12',
      created_at: '2026-01-12 10:20:00'
    }
  ]
}
```

## 3. 如何修改已有用户的足迹

直接打开：

- `VUE/src/mock/presetFootprints.js`

找到对应的 `userId`，修改该用户下面的 `footprints` 数组即可。

例如修改 `userId: 3` 的第一条足迹：

```js
{
  id: 301,
  travel_record_id: 3001,
  location_name: '杭州西湖',
  latitude: 30.243378,
  longitude: 120.150053,
  visit_date: '2026-03-08',
  created_at: '2026-03-08 08:50:00'
}
```

你可以直接修改：

- `location_name`
- `latitude`
- `longitude`
- `visit_date`
- `created_at`
- `travel_record_id`

## 4. 如何给已有用户新增足迹点

还是在同一个用户的 `footprints` 数组中追加一项，例如：

```js
{
  id: 304,
  travel_record_id: 3003,
  location_name: '雷峰塔',
  latitude: 30.231251,
  longitude: 120.148989,
  visit_date: '2026-03-10',
  created_at: '2026-03-10 17:30:00'
}
```

注意：

- `id` 不能和已有足迹重复。
- `travel_record_id` 建议也保持唯一或至少符合你的业务习惯。
- `latitude` 和 `longitude` 必须是有效坐标。

## 5. 如何新增第 21 个用户

直接在 `presetUserFootprints` 数组末尾继续追加一个对象，例如：

```js
{
  userId: 21,
  username: '旅行者21号',
  footprints: [
    {
      id: 2101,
      travel_record_id: 21001,
      location_name: '厦门鼓浪屿',
      latitude: 24.448091,
      longitude: 118.067562,
      visit_date: '2026-07-10',
      created_at: '2026-07-10 10:00:00'
    }
  ]
}
```

新增后，只要当前登录用户的 `id === 21`，页面就会自动显示这名用户对应的足迹。

## 6. 如何测试匹配效果

你可以通过以下方式测试：

1. 登录一个 `id` 在预置数据中的用户，例如 `1` 到 `20`。
2. 打开 `/footprints` 页面。
3. 地图上只会展示该用户匹配到的足迹点。
4. 足迹点会首尾闭合，形成封闭轮廓区域。

如果你登录的是不在预置列表内的用户，例如 `id = 25`，则页面不会显示足迹点。

## 7. 后续如果切换成真实接口

当前页面是“前端预置数据模式”，后续如果接入后端接口，可以直接改 `TravelFootprints.vue` 中的 `fetchFootprints` 方法：

当前是：

```js
footprints.value = getPresetFootprintsByUserId(currentUserId.value)
```

后续可以改成：

```js
const response = await footprintService.getCurrentUserFootprints()
footprints.value = response.data
```

这样就可以从后端按当前登录用户读取真实足迹数据。
