# 第一阶段本地构建与交接说明

## 1. 已采用的环境

- Windows，Node.js `22.20.0`，npm `10.9.3`。
- 本机检测到 HBuilderX `5.24.2026081301`。
- uni-app CLI 编译器 `3.0.0-5020420260813003`（输出标识为 5.24 Vue 3）。
- Vue `3.4.21`、Pinia `2.1.7`、Vite `5.2.8`、TypeScript `5.4.5`、ECharts `5.6.0`。
- 精确依赖见 `code/package-lock.json`。未升级或改写全局运行环境。

## 2. 本地构建命令

在 `code` 执行：

```powershell
npm ci
npm run check
npm test
npm run build:h5
npm run release:check
npm run build:app
```

H5 产物：`code/unpackage/dist/build/h5/`。App-vue 产物：`code/unpackage/dist/build/app/`。

构建脚本显式传入工程根目录 `UNI_INPUT_DIR`，不要求额外创建或复制 `src`。`pages.json` 注册 24 个第一阶段页面。H5 使用 hash 路由，根目录部署。

## 3. uniCloud 由用户自行上传

本轮没有登录、上传或修改 uniCloud 服务空间。后续上传时只选择 H5 编译目录中的文件，让 `index.html` 位于托管根目录。不要上传工程源码、`doc`、依赖缓存或签名材料。

发行检查只验证本地产物，不验证云端域名、额度、开通状态、HTTPS 和在线可访问性。实际托管网址由用户完成上传后填写，不以云存储或云函数域名替代。

## 4. Android 交接

`npm run build:app` 已配置为 App-vue 本地资源编译，输出不是 APK，不会自动进行云打包。`manifest.json` 的 AppID 留空，未编造或借用其他项目 AppID。

HBuilderX 后续操作：打开 `code`，申请或填写本项目 AppID，配置应用包名、图标和签名，再运行到设备或按自己的打包流程生成 APK。开发依赖及本地数据已具备，不需要启用云函数或数据库。

本机 `adb devices` 没有列出连接设备；未完成 Android 运行、点选回传、重启保存和系统返回键实测。不能将 App 资源编译成功记为真机验收。实际 Android 安装/运行证据需在设备可用后补齐。

本次没有生成签名 APK，没有向 Android 云打包服务上传代码，也没有执行任何 uniCloud 上传。
