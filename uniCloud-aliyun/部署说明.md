## 1. 缺少 appid 时如何发布

本项目的网页和云函数分开发布：

| 内容 | 推荐操作 | appid 的关系 |
| --- | --- | --- |
| 网页 `dist/` | 登录 uniCloud 网页控制台，在“前端网页托管”中上传静态文件 | 不需要在这个静态网页目录里添加 manifest 或 appid |
| 云函数 `zsh-ledger-api` | 用 HBuilderX 新建标准部署工程，取得真实 appid，关联已有空间后上传该函数 | 解决 HBuilderX 工程身份缺失；原网页架构保持不变 |

普通网页可从控制台按文件或文件夹上传，这是官方提供的托管方式。[官方说明：前端网页托管](https://doc.dcloud.net.cn/uniCloud/hosting.html)

本次核对的官方云函数开发流程使用 HBuilderX 创建工程、获取应用标识、关联空间并上传。没有确认当前阿里云 uniCloud 控制台提供通用的“上传 ZIP 覆盖云函数”入口，因此本文不让你依赖这个未经确认的菜单，也不把普通阿里云函数计算 FC 控制台当作 uniCloud 的等价替代。[官方说明：快速上手](https://doc.dcloud.net.cn/uniCloud/quickstart.html)

不必等原交付方补齐所有前端工程：只要你的 DCloud 账号有目标空间权限，就可以建立一个专门部署云函数的标准工程。appid 需要由 DCloud 正式分配，不要手写假的 `__UNI__...`。

## 2. 先确认更新的是原空间

1. 登录 [uniCloud 控制台](https://unicloud.dcloud.net.cn/)，使用原项目空间所有者或已授权的协作账号。
2. 找到现有阿里云空间，确认其中存在 `zsh-ledger-api` 和三个集合：`zsh-ledger-users`、`zsh-ledger-sessions`、`zsh-ledger-state`。
3. 对照本项目 `dist/cloud-config.js` 的 `apiBaseUrl`，核实它与该空间的云函数 URL 一致。对照 `staticSiteUrl` 核实前端站点。前端托管与云函数可能分属不同空间，应分别核对。
4. 若看不到原空间，需要空间管理员给当前账号授权；创建新 appid 不能替代空间权限，也不会把旧数据搬入新空间。

本次是更新功能，不需要新建业务空间、不需要重新创建用户或清空数据库。发布前保留当前线上网页和云函数代码备份，以便回退；台账可按原系统功能导出备份。

## 3. 用标准部署工程上传云函数

### 3.1 创建一次即可复用的部署工程

1. 在 HBuilderX 登录有目标空间权限的 DCloud 账号。
2. 选择“文件 → 新建 → 项目”，选择普通 **uni-app** 空白模板，启用 uniCloud，供应商选择阿里云。
3. 本项目已由 HBuilderX 生成 `tools/zsh-ledger-deploy/` 标准模板，直接打开该目录即可。不要同时在 HBuilderX 打开外层原项目：本次实测嵌套工程同时打开会导致云函数上传定位异常，关闭外层项目后上传成功。
4. 打开新工程的 `manifest.json`，在“基础配置 → uni-app 应用标识 AppID”确认已获得真实标识；如为空，使用“重新获取”。保留模板生成的其他入口文件。
5. 这是云函数管理工程，不需要将 `dist` 改写成 Vue，不需要运行其空白页面，也不需要打包 Android。

如果能取得原部署工程及原 appid，优先继续使用原工程。新的部署工程取得的是新的应用身份，不能声称它恢复了原 appid。DCloud appid 与服务空间 ID 是不同配置。[官方说明：DCloud appid](https://uniapp.dcloud.net.cn/dev/app/introduction.html)

### 3.2 放入本次的云函数代码

将以下整个目录复制到新工程对应的 `uniCloud-aliyun/cloudfunctions/` 下：

```text
本项目/uniCloud-aliyun/cloudfunctions/zsh-ledger-api/
├─ index.js
└─ package.json
```

形成：

```text
tools/zsh-ledger-deploy/
├─ manifest.json                  HBuilderX 生成，有真实 appid
├─ pages.json
├─ App.vue
├─ main.js
└─ uniCloud-aliyun/
   └─ cloudfunctions/
      └─ zsh-ledger-api/
         ├─ index.js              使用当前修改后的版本
         └─ package.json
```

模板和供应商目录名称以你安装的 HBuilderX 实际生成为准。不要复制成两层 `zsh-ledger-api/zsh-ledger-api`。

### 3.3 关联原空间并更新函数

1. 在新部署工程的 uniCloud 目录上右键，选择“关联云服务空间”或“关联服务空间或项目”，选择第 2 节确认的原阿里云空间。
2. 在 `cloudfunctions/zsh-ledger-api` 目录上右键，选择“上传部署”，等待上传成功。具体菜单文字可能随版本略有差异。
3. 到云控制台检查函数更新时间，并核对原 URL 化路径、运行配置、跨域设置与域名配置。
4. 保留现有 `/zsh-ledger-api` HTTP 路径。现有网页通过 HTTP 请求该函数，不需要改用 `uniCloud.callFunction`。
5. 本次 schema 没有修改，不需要执行全量“初始化向导”或导入样例数据。

注意：上传部署不要误选成对生产数据执行任意测试参数的“上传并运行”。确认部署成功后，用页面登录和业务流程验收。

以后每次修改，先把本项目的函数目录同步到部署工程，再上传。不要只修改临时复制目录而遗漏主源码。HBuilderX 的运行和上传说明见[官方文档](https://doc.dcloud.net.cn/uniCloud/rundebug.html)。

## 4. 从网页控制台更新网站

1. 在 uniCloud 控制台选择原网页托管所在空间，进入“前端网页托管”。这里不是保存 PDF 附件的“云存储”菜单。
2. 找到当前站点首页所在目录。原网站若在根路径访问，则该目录内应直接存在 `index.html`。
3. 将本项目 **`dist` 里面的文件及子目录** 上传到这个站点目录，覆盖同名文件；不要无意增加 `/dist/` 这一层路径。
4. 推荐先上传 JS、CSS 和新增依赖文件，最后覆盖 `index.html`。上传完成后检查首页及开发者工具网络请求，没有模块 404。
5. 本项目是直接提供静态文件的网页，无需先执行 npm 编译。`server.ps1` 只是本地预览工具，不上传。

正确的站点根目录结构：

```text
index.html
app.js
styles.css
cloud-api.js
cloud-config.js
ledger-data.js
vendor/
sample/
```

本次及上一轮功能合并更新，至少需要同步：

- `index.html`、`app.js`、`styles.css`。
- `ledger-data.js`：上一轮新增的金额分配模块，遗漏会导致页面初始化失败。
- 云端 `zsh-ledger-api/index.js`：包含多项目关联读取、省市打款字段过滤及保存保护。

完整上传 `dist` 可减少遗漏，但必须确认 `cloud-config.js` 仍指向原空间。它目前没有因本次修改而更换 URL。静态托管的文件/文件夹上传方式见[官方文档](https://doc.dcloud.net.cn/uniCloud/hosting.html)。

## 5. 推荐发布顺序与验收

1. 在业务不操作的时间段更新，先上传云函数，再上传网页。
2. 通知三个账号关闭旧页面，再重新打开；如仍看到旧样式，强制刷新。当前首页引用 `app.js?v=2.2.13`。
3. 管理员：进入预警台账 → 查看，修改维保单位、电话、下检日期、备注等，保存并刷新，核对回显。
4. 管理员：进入检验台账，“省市打款”汇总、表格和详情保持可见，原金额不变。
5. 分别登录两个业务员账号：检验台账的上述内容不可见；预警设备详情继续只读。
6. 回归上一轮：多项目分配金额、删除到账后的金额回退、维保筛选和设备批量删除。

仅上传网页能隐藏界面，但无法更新后端字段权限；本次必须同时更新云函数。新后端会从业务员响应中移除 `provincialPayment`，并保留数据库中的原值，避免业务员保存其他字段时把它改成零。

## 6. 常见问题

| 现象 | 优先核对 |
| --- | --- |
| 新部署工程仍提示缺少 appid | 是否导入了标准工程根目录；根 manifest 是否有 DCloud 实际分配的标识；账号是否已登录 |
| 关联列表找不到旧空间 | 当前 DCloud 账号是否具有该空间权限；所选云供应商是否正确 |
| 更新后网页白屏 | `ledger-data.js`、PDF.js 等依赖路径是否完整；`dist` 是否多套了一层 |
| 页面还是旧版 | 是否更新了正确的站点/目录；首页缓存参数是否为新值；关闭旧标签后强制刷新 |
| 新页面正常但业务员接口仍含省市金额 | 是否将新云函数上传到了 `apiBaseUrl` 实际指向的空间 |
| 登录或保存出现跨域错误 | 原页面域名、云函数来源白名单和平台跨域配置是否仍匹配 |
| 关联新空间后旧数据消失 | 新空间不包含原数据；本次更新应关联原空间而非新建空空间 |

本次通过已登录的 HBuilderX CLI 完成真实 appid 创建、原空间关联、云函数上传和网页托管部署；远端代码回读核对通过，线上登录页正常。没有执行生产业务数据的新增、修改或删除，登录后的三个账号业务验收仍需按第 5 节进行。
